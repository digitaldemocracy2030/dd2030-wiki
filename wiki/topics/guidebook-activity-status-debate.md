2026年10月2日に公開された新規参加者向けガイドブック（dd2030.org/guide-book、→ [[コミュニティ運営]]）の目次をきっかけに、「どのプロジェクトが動いているか」をガイドブックに書くべきか、書くとしたら誰がどう判断するのか、が `#2_コミュニティ運営` で議論された。結論は、**活発かどうかを誰かが宣言する文章は載せず、読者が自分で判断できる材料（リポジトリへのリンクなど）を置く**。「構えている人をほぐす」役割はガイドブックから切り離し、Meetup など別の活動に委ねる。

## 背景

ガイドブックは[[コミュニティ運営]]定例で2025年から準備されてきたオンボーディング資料で、[[主要メンバー|小野翔太（モアイ）]]が website リポジトリの `src/guide-book/` に統合し、10月2日に「たたき台」として公開した。全体定例（2026-09-05〜09-26）でも「たたき台ができたので Discord で公開し、意見を募りながら編集する」と共有されていた。

公開時の目次は次の構成だった。

1. DD2030とは何か
2. 5つの取り組みの関係 — ブロードリスニング・[[広聴AI]]・[[いどばた]]・[[Polimoney]]・[[コアループ|Coreloop]]
3. 現在動いているプロジェクト — Project Coreloop「オンライン広告詐欺対策」
4. 参加方法
5. 参加から実践の流れ
6. 問い合わせ先

## 議論の経緯（2026-10-04〜10-05）

**発端（大木真吾）。** 第2章で5つの取り組みを並べたあと、第3章「現在動いているプロジェクト」が Coreloop だけなのは違和感がある。他の4つと同様に扱ってよいのではないか。

**小野の説明と案。** 書き始めた時期に Coreloop のチャンネルが活発だった影響がある。対案として、「動いている」を「開発」と「活用」に分けて書く、活発度を true/false か3段階で示す、「開発に参加したいので現状を教えてください」というテンプレートを用意して Slack で聞いてもらう、を挙げた。

**大木の反論。** 開発が活発かどうかは、誰かが決めたり言ったりするものではなく、それぞれの人が判断するもの。大事なのは、その判断に必要な材料（タイムスタンプ付きで活動が残っていること等）を、運用コストをかけずに用意すること。「聞いてもいいけど、聞かないと分からない状態にはしない」。そもそも読者はなぜ活発かを知りたいのか、と問い返した。

**小野の整理。** 誰がなぜ知りたいかを考えると、主に「開発に知見のある人」が「実質開発されていないか」を確かめたい、あるいは「構えて」いて現状を知りたい場合が多い。GitHub を見られる人は自分で確認できるので、ガイドブックに書くべきはリポジトリへのリンクかもしれない。一方で、非開発者が発言してよいか探っているときの指標にもなりうる。ただし「構えている状態をほぐす」のがガイドブックの役割だとすると、活発かどうかが書いてあるだけでは足りない。本当に安心なのは誰かが Meet で現状を説明し不安を聞くことだが、そのコストを減らすのがガイドブックでもある。

**大木による課題の切り分け。**

- ガイドブックの役割: DD2030 をまだあまり知らない人に、正しい情報をコンパクトに伝えること
- Meetup など他の活動: 構えている状態を何とかすること

「人によって何が課題だと思っているかが違う」と添えた。

**小野の受け止め。** ガイドブックの役割をざっくりとしか考えていなかったので、公開したことで議論できてよかった。「オンボーディングコストを上げないようにしつつ、参加のハードルを少しでも減らす」と考えていたが、ハードルが何かをリスト化してみる。翌10月5日、ブラッシュアップの場として Discord サーバーを試験的に開くと告知した。

## 何が決まったか

- 状況によって変わる記述（どのプロジェクトが活発か）は、ガイドブックに入れると更新が追いつかなくなるので入れない。
- 判断材料として、各プロジェクトのリポジトリと紹介ページへのリンクを置く。活発度の判断は読者に委ねる。
- 「構えている人をほぐす」はガイドブックではなく Meetup 等の役割とする。

## その後の反映

10月30日に小野（GitHub: moai-redcap）がマージした website PR #229 で、ガイドブックは次のように改訂された。

- 第3章は広聴AI・いどばた・Polimoney・ブロードリスニング本・Coreloop を同列に「現在アクティブなプロジェクト」として紹介し、各項目に紹介ページと GitHub へのリンクを付けた。活発度のラベルは付けていない。
- 第4章「参加方法」にプロジェクト一覧をリポジトリ・サイトのリンク付き表としてまとめ、第3章へリンクした。
- 各章から「整備中」バナーを外して目次に集約し、章冒頭に要約を付けた。

## 関連する運営上の考え方

この議論で出た「聞かないと分からない状態にしない」は、2026年9月の[[topics/nl-data-collection-tools-collaboration|広聴AI×いどばた合同ミーティング]]を非同期の書き出しだけでクローズした判断や、[[Slackログアーカイブ]]・[[OSS Weekly Reporter]]で活動をタイムスタンプ付きで残す取り組みと同じ方向にある。活動の記録を機械的に残し、人が説明しなくても現状が分かる状態を作ることが、dd2030 の運営で繰り返し選ばれている。
