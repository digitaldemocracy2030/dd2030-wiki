## 主要イニシアチブ

### MEETUP（オフラインイベント）
ブース出展形式＋アンカンファレンスを組み合わせた形式。過去に[[events/2025-04-12-1day-meetup|MEETUP #1（4/12）]]、[[events/2025-05-25-meetup-2|MEETUP #2（5/25）]]、[[events/2025-07-18-meetup-3|MEETUP #3（7/18）]]を開催。2026年は日程調整が続き、Meetup 単体は未実施のまま。2026年6月19日の定例では「年1回の大きなカンファレンスだけでなく、月1回程度の小さな場（ハッカソン等）が新しい協力者の入口になる」「モアイが全部抱えると持続しないので、企画担当を置き、進捗が見える状態にして他の人が引き取れるようにしたい」と整理された。大きなイベントとしては2026年8月2日に[[events/2026-08-02-digital-democracy-summit|デジタル民主主義サミット2026]]が開催され、コミュニティ運営定例の3名（遠藤・モアイ・大木）は会津での構想を軸にしたセッションを提案した。

### ウェルカムミート
新規参加者向けのオンボーディングイベント。[[events/2025-06-21-welcome-meet-2|ウェルカムミート#2（2025-06-21）]]では、参加直後の人や普段発言しづらい人に向けて、dd2030の全体像と各プロジェクトへの関わり方を紹介した。[[events/2025-11-28-welcome-meet-3|ウェルカムミート#3（2025-11-28）]]では、「理解・つながる」入口から「貢献する」導線へ進む設計がより明示され、具体的なタスクリスト、定例参加、GitHub Issue、Slack bot DM などが検討された。ガイドブック・Historyページの紹介、効果測定（非アクティブ→アクティブ率）も検討中。

### ガイドブック
新規参加者向けに dd2030 の全体像と参加方法を説明するドキュメント。**2026年10月2日に dd2030.org/guide-book として公開**され、website リポジトリの `src/guide-book/` で管理されている（誰でも PR でコントリビュートできる）。

### Slack → Discord 移行の検討（2026年5月〜）
2026年5月のコミュニティ運営定例と全体定例で、Slack から Discord への移行が議論された。

- **論点（5/15 コミュニティ運営定例、5/16 全体定例）**: Slack は運用を楽にする機能が軒並み有料で、有償版は月額数百万円規模になり現実的でない。Discord はパブリックチャンネルがデフォルトで見える設計のため、新規参加者が自分でチャンネルを探して入る必要がある Slack よりオンボーディングのコストが低い。一方で、料金体系が変わるリスク、セルフホストする場合のサーバー代、絵文字数の制限、約1,600人のメンバー資産を切り捨てることへの懸念、「移行すれば活性化するかは不確実」という指摘もあった。「過去ログが消える」懸念に対しては、公開チャンネルのログはすでに GitHub に保存されている（[[Slackログアーカイブ]]・[[OSS Weekly Reporter]]）ので問題にならない、と整理された。
- **方向性**: 一般社団法人化のタイミングで切り替える案、全体で動くのではなく移行したいチームから移行する案が出た。5/22 にこの定例と全体定例の議論をまとめ、「全体お知らせ」で意見を募ることになり、以後の全体定例では「Slack→Discord への移行に関するご意見受付中」が継続項目として掲示された。
- **官庁・政治家側の懸念確認**: 「官庁の方が Discord を使えるのか」が懸念として残り、6月〜7月に Slack で政治家・官庁関係者に確認した。区議会議員と区民のコミュニティで Discord が使われている例があるという情報（渉外チーム経由）が得られ、他の懸念は寄せられなかった（7/18 全体定例）。「正式な移行ではないことを明記して試験的に全体告知する」案が出た。
- **現状（2026年10月末）**: 全体の移行は決まっていない。10月5日にガイドブックのブラッシュアップ用として Discord サーバーが試験的に開かれた段階。

### 会計プロボノの募集（2026年10月）

## オンボーディング課題

いどばたでの意見募集（2026年4月）で以下の参加障壁が確認された:

- 「何をすればよいか分からない」
- 「誰に聞けばよいか分からない」
- 「情報が見つけにくい」
- 「関わり方のイメージが持ちづらい」

### 背景
- 「初めに読んでね」チャンネルがあるがメンテされていない
- Canvasがあるが見つけられていない
- メッセージのピン留めが3ヶ月で流れる
- エンジニアが貢献しやすい構造になっており、非エンジニアの参加障壁が高い

### 改善案
- 3ヶ月ごとに「この3ヶ月のまとめ」を流す
- Historyページへの動線確保（Slackへの毎週投稿、自動化）
- 「はじめに読んでね」のメンテナンス → 2026年5月8日に Google ドキュメント化して `#0_はじめに読んでね` にピン留めし、6月19日に完了扱いとした

### 2026年5月〜6月の整理

- **いどばたでの意見募集（2026年4月〜5月）**: 「デジタル民主主義2030プロジェクト コミュニティ改善のための意見募集」を[[いどばた]]で実施し、レポートを見ながら定例で対応を検討した。上記の参加障壁はこの結果から抽出されたもの。
- **ToDo 管理の置き場所（5/1）**: GitHub で ToDo を管理するとエンジニア以外がアクセスしづらいため、議事録内の TODO 欄に切り出して管理することにした。
- **根本課題の認識（6/19）**: コミュニティ運営の一番の課題は「整理されていないこと」。何をやるべきか、どの領域にどんなタスクがあるか、誰がどこに関わるとよいか、どこまで進んでいるかが見えないため、手伝いたい人がいても入口を見つけにくい。OSS コミュニティでの「コミュニティ運営」は開発以外のすべて（広報、Web サイト更新、ドキュメント整理、オンボーディング、イベント運営、外部対応、事例整理、問い合わせ対応、プロジェクト状況の見える化）を含むという整理のもと、領域をカテゴリ分けし、ライトに関われる小さなタスクを一覧化する方向になった。
- **活動が外から見えない問題（6/19）**: 広聴AIを使おうとする自治体や、いどばたに興味を持つ団体との接点があるのに Web サイトにタイムリーに載らず、外から「動いていない」ように見える。しっかりした記事は重いので「1文程度の短い活動メモ」から始める。ただし外部の相手がいる場合は公開可否の判断が必要。
- **活動まとめ・Slack ログ・Wiki の関係（6/19〜7/11）**: 毎週届く活動まとめ PR を手動マージし続けるか、別の仕組みに移るかを確認することになった。7月に西尾が作っていた dd2030-wiki を公式リポジトリへ移し（[[topics/dd2030-wiki-repository-transfer|dd2030-wiki の dd2030 org 移行]]）、OSS Weekly Reporter の代替的な活動把握先、ガイドブックからのリンク先として継続的に使える状態にする方針が全体定例（7/11）で共有された。
- **Web サイトのアナリティクス（6/19）**: Google タグ等が入っていないことを確認し、ToDo / Issue 化することにした。

2026年8月中旬、ボードメンバーの鈴木健が全体定例で「各プロジェクトの戦略会議をしよう」と提案した。[[広聴AI]]・[[いどばた]]・[[Polimoney]]のプロジェクトごとに、鈴木健とプロジェクトメンバーがオープンに話す場（Google Meet、30分〜1時間、2026年9月以降）を設ける構想で、狙いは現状の課題をボードメンバーがサポートし、1年の方向性を話すこと。各プロジェクトが9月以降の候補日を出す形で調整が進み、広聴AIには自治体利用の観点から関治之（Code for Japan）も招く方向で検討された。
