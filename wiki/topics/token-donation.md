2026年10月、`#2_開発_広聴ai` で「AI サブスクリプションに付いてくる使い切れないトークンを、OSS 開発や他の人のために回せないか」というアイデアが話された。結論は出ておらず、Issue にトークンで支援して AI が PR を作る「クラファン型」の構想が共有された段階。

## 発端

- 10/16、中山心太（tokoroten）が「Claude の Max プランに API の無料クレジットが付いてくるので、これを[[広聴AI]]に突っ込みたい。Claude 対応をしたい」と投稿（Anthropic は埋め込みモデルを提供していないため、埋め込みはローカルモデルなどで補う必要があると後に分かった。Issue #1042）。
- 10/17、kuboon が「私も余らせそうなので何かに使いたい。『トークンドネーション』というアイデアを Code for Japan で見かけたが、具体的な実現方法がまだ思いつかない」と続けた。

## 出たアイデア

**Issue 駆動の自動実装（大木真吾）。** Issue に特定のキーワードやタグが付いていると、支援者のトークンを使って AI が PR を作るところまでやる。そうなると Issue がきちんと管理されていることが重要になる。「何が Issue なのか言語化されていないプロジェクトには、どう関わればいいのか分からないから貢献が集まりにくい」のはトークンの話がなくても同じ。

**誰に渡すと意味があるか（西尾泰和）。** 月額200ドルのプランには API 換算で7,600ドル相当のトークンが来るが、1週間の期限付き。使い慣れた人でも使い切れないほど多いので、使い慣れていない人に寄付しても使いこなせないし、期限はさらに短くなる。意味があるとすれば、AI を使いこなして面白い開発をしているが可処分所得の少ない中高生のようなケース。別案として、小学生向けの科学質問箱を通年化し、質問を機械可読な形で GitHub に入れ、支援したい大人がスキルを発動させると Deep Research して年齢に合わせた解説を生成する、という構想も出した。

**クラウドファンディング型（大木真吾、10/18）。** Issue に対して「これを実現してほしい」人がトークンで支援し、AI が実装して PR を作る。広聴AIの利用者自身が欲しい機能を Issue にし、自分のトークンで AI に PR を作ってもらうこともできる。マージされるかは別として、自分で開発できなくても OSS に貢献しながら欲しい機能の実装まで進められる。これまでは要望を Issue に出せても、実装したい人・できる人が必要だった。AI が入ることで「できるといいと思う、だから支援したい」人まで開発に直接関われるようになり、コミュニティの外からもニーズや実装案が集まるかもしれない。「案外、これをどうやるのかの手順を案内するのが大事かもしれない」。

## 現状

- 実装や運用の決定はない。
- 西尾は10/18、余ったトークンを使って週末に自動で実験を繰り返す仕組みを試した（「あんまり実験してくれなくて余った」）。同月の Issue 棚卸し（open 89件を複数エージェントで照合）は、余ったトークンの使い道の一例になっている。
- 広聴AIの Issue 管理が整っていることが前提になる、という点は [[広聴AI]] の10月の棚卸しと接続している。
